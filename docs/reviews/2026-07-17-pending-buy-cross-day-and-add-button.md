# 待确认买入跨日与加仓按钮审查

日期：2026-07-17

## 用户现象

- 2026-07-16 15:00 前登记的 `5000.00` 元买入，跨日后首页看起来像被清除。
- 对同一基金再次登记 `5000.00` 元时，点击“确认加仓”没有可见反馈。

## 核对结果

生产数据库中的原记录没有被删除：基金 `017968` 仍保存 `PendingBuyAmount = 5000.00`、`PendingTradeStatus = pending_buy`、交易日 `2026-07-16`、预计确认日 `2026-07-17`。问题来自读取与交互层，不是数据库丢失。

金额验算：

```text
基金确认金额 42194.95 + 待确认 5000.00 = 基金当前展示 47194.95
账户确认金额 99060.50 + 待确认 5000.00 = 账户当前展示 104060.50
确认成本 55916.92 - 待确认本金 5000.00 = 50916.92
持有收益 42194.95 - 50916.92 = -8721.97
```

## 根因

1. 读取逻辑把“预计确认日已到”误当成“交易已经确认”，导致 pending 在页面和账户汇总中被隐藏。
2. 有效 `DailyArchive` 承接当前金额时又把 pending 强制归零。
3. 后端重复登记返回纯文本 `400`，前端固定调用 `response.json()`；解析失败后只出现泛化网络提示，短时提示又容易被忽略。

## 修复口径

- 交易是否仍在途由显式 pending 状态决定；预计确认日只决定预计何时开始参与收益。
- 交易日不参与当天收益；从预计首个收益日起可进入收益基数和有效份额。
- 实际结转前仍展示待确认本金，并继续阻止重复登记。
- 有效档案承接首页时使用 `确认金额 + 待确认金额`，正式 `DailyArchive` 仍只保存确认金额。
- 首个收益日按 `确认基数 + 当日收益 + 待确认本金` 计算，禁止重复添加本金。
- 加仓接口错误统一为 JSON；WebApp 同时兼容 JSON 和文本错误，并在弹窗内保留可见原因。
