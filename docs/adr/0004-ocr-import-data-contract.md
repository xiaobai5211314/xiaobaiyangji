# OCR 导入字段契约

## 状态

Accepted

## 背景

蚂蚁基金 App 截图通过百度 OCR API 提取文本，并通过基金 OCR 导入流程（`FundController` 的 preview/confirm 流程，或后续拆分出的对应基金 OCR 服务）写入数据库。股票截图由 `StockOcrParserService` 负责解析；本 ADR 约束的是基金 OCR 导入字段契约，不绑定股票 OCR parser。需要明确哪些字段是关键契约字段，缺失时如何处理。

## 决策

OCR 导入必须提取以下字段（按优先级排列）：

| 优先级 | 字段 | 说明 | 缺失处理 |
|--------|------|------|---------|
| P0 | 当前金额 | 蚂蚁 App 显示的持有金额，可能包含买入待确认金额 | 缺失则标记截图无效 |
| P1 | 昨日收益 | 蚂蚁 App 显示的前一日收益 | 缺失则该字段为空 |
| P1 | 持有收益 | 蚂蚁 App 显示的累计收益 | 缺失则该字段为空 |
| P2 | 持有收益率 | 持有收益 / 持仓本金 | 可从持有收益和当前金额推算 |
| P2 | 确认日期 | 收益确认的日期 | 缺失则使用截图日期 |
| P3 | 待确认买入金额 | 已提交但未确认的买入 | 缺失则该字段为空 |
| P3 | 份额 | 明细页可能显示；常规持仓列表截图通常不显示 | 缺失时可用官方净值从当前金额自动反推 |
| P3 | 成本金额/成本价 | 明细页可能显示；常规持仓列表截图通常不显示 | 明细页给出成本价和份额时按 `成本价 × 份额` 校准；缺失时可用当前金额和持有收益推导成本金额 |
| P3 | 已实现收益 | 普通持仓页和资产详情页通常不提供可核验的确认卖出收益 | OCR 不推导、不覆盖；只由确认卖出流程写入 |

### 口径约束
- "当前金额"是平台持仓金额；OCR 导入时不得用其他字段逆推。
- OCR 是当前金额的校准源，不是要求用户每天导入的唯一来源；无新鲜 OCR 时，系统必须允许官方净值或盘中估值继续滚动首页当前金额。
- `OcrSnapshotDate` 与北京时间当前自然日相同时，该 OCR 当前金额默认是截图时点的首页展示边界，盘中估值不得再次叠加收益。截图后正式净值更新且可靠份额证明金额相差超过 `0.01` 元时，快照退出当前金额优先级并由官方金额自愈；跨过 00:00 后旧快照也退出当前展示优先级，但其正式归档记录保持不变。
- 存在"买入待确认金额"时，确认持仓金额必须按 `当前金额 - 买入待确认金额` 计算。
- "昨日收益"只能用于"昨日确认收益"和"盈亏日历"，不得用于反推其他金额。
- "持有收益"是蚂蚁 App 的累计收益，不得用 `当前金额 - 昨日收益` 修正。
- "买入待确认金额"未确认份额前不得参与今日收益、持有收益率本金、正式历史确认金额。
- 同时存在待确认买入和成本字段时，OCR/资产详情页已确认成本视为确认持仓成本，不再减待确认金额；只有手工交易形成且标记为未确认 `purchase_amount` 的总成本才扣除待确认本金一次。
- 用户使用常规持仓截图导入时，不要求手工补查份额或成本价。系统可自动计算缺失的份额和成本金额：份额按 `当前金额 / 官方净值` 校准，成本金额按 `当前金额 - 持有收益` 校准。用户使用资产详情页截图导入时，若 OCR 到 `持仓成本价` 和 `持有份额`，系统优先按平台字段写入份额与成本，并用 `持有收益 - (当前金额 - 成本金额 + RealizedProfit)` 校准 `PlatformHoldingAdjustment`。OCR 不得把该差额写入 `RealizedProfit`。
- 常规持仓 OCR 的自动派生份额和成本必须标记为未确认来源；资产详情页识别出的平台份额/成本必须标记为确认来源。后续普通 OCR 只能补齐未确认且无更高优先级交易来源的字段，不能覆盖平台确认值或买入交易推导值。
- 自动推导的份额和成本金额是后续估值辅助字段；同日有蚂蚁 OCR 快照时，昨日收益和已归档日历继续以 OCR 字段为准。正式净值尚未更新时首页金额、持有收益也以截图为准；正式净值更新后，仅可靠份额可在超过 `0.01` 元异常阈值时回正当前金额，持有收益随回正金额滚动。

### 名称修正映射
- OCR 识别的基金名称可能与标准名称不一致（如缩写、空格差异）。
- 用户确认导入时，系统将 OCR 名称与正确基金代码/名称的映射存入 `OcrCorrection` 表。
- 后续导入同一 OCR 名称时可自动匹配已知基金代码，减少用户手动确认次数。

### 降级策略
- P0 字段缺失 → 截图标记为无效，提示用户重新截图。
- P1 字段缺失 → 降级为 `official-nav-pending` 待确认档案。
- P2/P3 字段缺失 → 能从当前金额、持有收益或官方净值安全推导的字段自动推导；不能推导的字段留空，不影响主流程。

## 影响

- 基金 OCR 导入流程必须提取上述字段；股票 OCR 的 `StockOcrParserService` 不承担本 ADR 的基金字段契约。
- OCR 结果预览页面必须展示提取到的字段供用户确认。
- 用户确认后数据写入 `MyFundConfig` 的蚂蚁确认字段。
- `MyFundConfig.HoldShares` 可能由官方净值校准写入；`MyFundConfig.CostAmount` 在 OCR 未提供成本价时可由当前金额和持有收益校准写入。
- 份额和成本的确认状态及来源分别写入 `HoldSharesAreConfirmed` / `HoldSharesSource` 与 `CostAmountIsConfirmed` / `CostAmountSource`，用于执行来源优先级。
- `MyFundConfig.PlatformHoldingAdjustment` 可由资产详情页成本价、份额、当前金额、持有收益和已有 `RealizedProfit` 校准，用于后续无新鲜 OCR 时保持持有收益口径。
- `MyFundConfig.RealizedProfit` 只由确认卖出更新；资产详情 OCR 导入不得修改它，前端“已落袋”只表示真实确认卖出收益。

## 验收规则

- 提取字段与蚂蚁 App 截图一致。
- 常规持仓截图不含份额/成本价时，用户确认 OCR 后无需额外手工核对这些字段；系统自动派生值不得改变 OCR 提取到的当前金额、昨日收益和持有收益。
- 已有资产详情页平台份额/成本时，随后导入常规持仓截图，平台值不得发生变化；买入成交净值和金额形成的交易派生值也不得被普通 OCR 的两位金额反推值覆盖。
- 晚间导入已经包含当日最终净值的同日截图后，首页账户总金额应等于 OCR 当前金额合计；若截图早于正式净值更新，可靠份额揭示超过 `0.01` 元的金额变化时允许自动回正。进入下一自然日后，今日收益从 0 开始且旧 OCR 不再锁定当前展示金额。
- 缺失 P0 字段时明确提示"截图无效，请重新截图"。
- 缺失 P1 字段时降级为 pending 而非写入正式档案。
