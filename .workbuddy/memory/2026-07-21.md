## WebApp 三处前端 Bug 修复（software-bugfix-webapp-3issues）

用户报告 3 个问题（guzhicdn 域名下）：
1. 场外涨幅榜「网络错误」一直转圈
2. 浅色主题文字发虚（用户称"字体影响文字"）
3. 收益率不一样

### 根因与修复（commit 4b74842，已推送 + CDN 刷新）
- **Bug A 网络错误**：`fetchMarketRanking` 用裸 `fetch('/api/fund/market-ranking?...')` 相对路径，CDN 域名下打到 CDN 自身（无后端）→ 404。改为 `apiFetch(url)`（自动拼 `API_BASE='https://guzhi.21212121.xyz'`）。Playwright 实测：绝对地址返回 200 + 真实数据。
- **Bug B 浅色对比度**：`.radar-badge`/`.performance-status.win`/`.metric-up`/`.performance-status.loss`/`.metric-down` 在 CSS 类里硬编码 `#ff4d4f`/`#10b981`，原浅色覆盖规则只匹配内联 `style=`（匹配不到类）。新增 `:root[data-theme="light"]` 类选择器覆盖，深色值 `#b91c2b`/`#006b46`。Playwright 实测 5 个类计算颜色均为深色。
- **字体栈**：`--font-display`/`--font-body`/body 补回 `-apple-system, BlinkMacSystemFont, "Segoe UI"`。
- **收益率不一样**：非 bug。涨幅榜 `dailyRate`=东方财富全市场数据，与持仓 `todayRate`（后端按持仓算）来源不同属正常；另 CDN 旧 HTML 缓存会导致 guzhicdn/guzhi 版本不一致，本次推送已触发 upyun 缓存刷新。

### 流程
主理人分析 → 工程师(寇豆码)改 `wwwroot/index.html`（+22/-4）→ QA(严过关)代码级验证 NoOne 通过 → 提交推送 → CDN 部署成功 → Playwright 生产实测 Bug A/B 均生效。

### 关键事实
- `apiFetch(path)` 定义于 index.html ~L6324，自动 `fetch(API_BASE + path)`。全站除 market-ranking 外均已用 apiFetch。
- 浅色主题覆盖规则（`[style*="color:..."]`）只匹配内联 style 属性，CSS 类硬编码色需单独加类选择器覆盖。

## 今日收益率两处显示不一致修复（software-bugfix-rate-mismatch）

用户报告首页 Summary「今日确认收益率 +2.77%」与 Performance Curve「今日收益 +4.87%」数值不一致（差 2.1 个百分点）。

### 根因
两个数字来自不同后端接口、不同口径：
- Summary `todayPerformanceRate`：分母用 `todayPerformanceRateBase`（确认持仓口径，排除 pendingBuy），符合 ADR 0001。
- Performance Curve `myTotalRate`：`GetTodayPerformanceCurveAsync` 内 `totalPrincipal` 原来优先用 `latestPortfolioTotal.Assets`（DailyArchive TOTAL，可能含待确认买入）→ 分母口径不一致导致收益率偏高。

### 修复（commit e9c0a13，已推送 + 后端部署完成 run 29831965917 success）
`totalPrincipal` 改为统一使用 `quotedPrincipal`（= `series.Sum(s => s.Amount)`，`BuildTodayPerformanceSeries` 内每个基金 amount 已通过 `GetDailyBaseAmount` 排除 pendingBuy）。删除了方法内仅服务该 fallback 分支的 DailyArchive TOTAL 查询块（避免未使用变量警告）。仅影响 today 周期，历史周期走独立路径。
build 0 错误 0 警告。QA 代码级验证 NoOne 通过。

### 关键事实
- `BuildTodayPerformanceSeries` (L4861)：每个基金 amount = `GetDailyBaseAmount(config, todayDash, pendingBuyAmount)`，已排除待确认买入。
- ADR 0001 规则：收益率分母必须使用确认持仓金额，排除待确认买入。
- 用 Playwright 无法验证（需登录 username），生产验证需用户刷新页面确认两处数字一致。

## 板块方向列真实连续涨跌天数（software-sector-streak-bprime）

用户选 B'（公开口径）：板块「方向」列显示真实连涨/连跌天数，基于东方财富基金历史净值计算，所有用户一致、公开可看。

### 根因
- 原 `StreakDays` 只存 ±1/0（当日方向标记）；前端 L5510 只显示"连涨/连跌"文字、L5951 显示"N天"但数据恒为 0/1。
- `GetSectors` 是公开接口（前端 `fetchSectors` 裸 `fetch` 不带 token，Redis 共享缓存），**不能**按 per-user 持仓 DailyArchive 反推（原方案 B 不可行）。故改公开口径。

### 实现（QA NoOne 全 PASS，dotnet build 0 错 0 警）
- `FundController.cs` 新增：`SectorNavDay` record、`FetchFundNavHistoryAsync`（东方财富 `api.fund.eastmoney.com/f10/lsjz` + `Referer: https://fundf10.eastmoney.com/`）、`FetchFundNavHistoryCachedAsync`（IMemoryCache 8h + `SemaphoreSlim(12)` + 4s 超时）、`ComputeSectorStreakDays`（按日期对齐求每日均值→连续同号天数，连涨正/连跌负）。
- `BuildSectorRadarPayloadAsync` 汇总循环替换原 ±1/0 为真实计算；每板块限前 20 只匹配基金、跨板块基金去重。
- 前端 `wwwroot/index.html` L5510 由纯文字改为与 L5951 一致的 `{{ item.streakDays>0?'+':'' }}{{ item.streakDays || 0 }}天`。
- 浅色主题覆盖色实际为 `#b91c2b`/`#006b46`（工程师一度误搜 `#b91c2c` 导致虚惊，实际覆盖规则存在且正确）。
- `GetSectors` 公开性/`Rate`/多级缓存均未变；历史净值失败仅该列显示 0 天，不阻塞。
